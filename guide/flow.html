프로젝트 흐름 & 데이터 형식

증상 입력부터 진료과·병원 안내까지의 흐름과, 각 단계에서 데이터가 어떤 형식(JSON)으로 오가는지 정리합니다.

1. 전체 동작 흐름

2. 데이터는 전부 JSON으로 오간다

프론트 ↔ 백엔드는 POST /api/chat 하나로 통신하고, 요청/응답 모두 JSON입니다. 내부적으로 에이전트는 State라는 딕셔너리를 노드마다 채워가며 넘깁니다.

정확한 필드 정의는 코드에 있어요 → 요청/응답: backend/api/schemas.py, 내부 State: backend/agent/state.py. 이 두 파일이 "공유 계약"이라 바꿀 때 팀 공지 필수.

3. ① 프론트 → 백엔드 (요청)

POST /api/chat 사용자가 증상을 입력하면 프론트가 이 형식으로 보냅니다.

{
  "message": "어제부터 오른쪽 아랫배가 아프고 열이 나요",
  "lat": 37.5665,
  "lng": 126.9780,
  "history": [
    { "role": "user", "content": "..." },
    { "role": "assistant", "content": "..." }
  ]
}

4. ② 에이전트 내부 (State가 단계마다 채워짐)

하나의 State 딕셔너리를 노드들이 읽고 → 필드를 채워 → 다음 노드로 넘깁니다.

단계(노드)추가/갱신되는 필드담당
① collect (증상 수집)symptoms, need_more_info박근령
② triage (응급도 판별)emergency박태준
③ classify (진료과 분류)departments (Top-N + 근거)박태준
④ search (의료기관 검색)hospitals최건
⑤ (결과 조립)final_message박근령

State가 흐르며 커지는 모습:

// collect 이후
{ "user_input": "...", "symptoms": ["우하복부 통증", "발열", "구토"], "need_more_info": false }

// triage 이후 (응급 아님)
{ ..., "emergency": false }

// classify 이후 (RAG 근거로 Top-N)
{ ..., "departments": [
    { "name": "외과",       "score": 0.87, "reason": "우하복부 통증+발열 → 충수염 의심" },
    { "name": "소화기내과", "score": 0.63, "reason": "위장관 염증 가능성" }
]}

// search 이후 (공공 API 결과)
{ ..., "hospitals": [
    { "name": "서울튼튼외과의원", "dept": "외과", "distance_m": 320, "is_open": true, "phone": "02-000-0000" }
]}

5. ③ 백엔드 → 프론트 (응답)

최종적으로 State를 ChatResponse로 변환해 돌려줍니다. 프론트는 이것만 보고 화면을 그립니다.

{
  "reply": "말씀하신 증상으로는 외과 진료가 가장 적합해 보여요.",
  "emergency": false,
  "need_more_info": false,
  "departments": [
    { "name": "외과", "score": 0.87, "reason": "우하복부 통증+발열 → 충수염 의심" },
    { "name": "소화기내과", "score": 0.63, "reason": "위장관 염증 가능성" }
  ],
  "hospitals": [
    { "name": "서울튼튼외과의원", "dept": "외과", "distance_m": 320, "is_open": true, "phone": "02-000-0000" }
  ]
}
응급일 때는 분류를 건너뛰고 { "reply": "...즉시 119...", "emergency": true } 형태로 바로 반환합니다. 프론트는 emergency === true면 119 안내 화면을 띄웁니다.
