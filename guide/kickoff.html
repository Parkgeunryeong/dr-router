순서는 딱 셋입니다. ① 회의로 정하기 → ② 박근령이 관통 → ③ 각자 병렬. 이 순서만 지키면 안 꼬여요.

먼저 이것만 기억하세요 — "진료과 목록"과 "State 스키마" 2개를 회의에서 먼저 확정하면, 나머지는 각자 달릴 수 있습니다.

STEP 1 · 첫 모임에서 "함께" 정할 것 (30분)

각자 코딩 시작 전에 아래를 확정하세요. 안 정하고 시작하면 나중에 다 충돌나요.

정할 것결정주도
□ State 스키마 (state.py)필드 확정 → 동결박근령
□ 진료과 목록 (예: 15개)어떤 과를 다룰지전원
□ API 계약 (schemas.py)요청/응답 형식최건·박근령
□ GPT 모델명수업이 준 정확한 이름전원
□ 공공 API 키 발급 방식1명 공유 vs 각자최건
□ MVP 범위(데모 경계)"어디까지 만들면 끝"전원
□ 파이썬 버전 · 브랜치 규칙예: 3.11, feat/이름-작업전원

STEP 2 · 착수 순서

0

Phase 0 — 첫날 (함께)

  • □ 전원: clone → venv → pip install (세팅 페이지대로)
  • □ 박근령: state.py 확정 → 팀 공지 ⭐
  • □ 최건·박근령: schemas.py 확정
  • □ 이상현: 요구사항 정의서 FR 초안 → 회의에서 진료과 목록·MVP 확정
  • □ 최건: 공공데이터포털 키 발급 신청
1

Phase 1 — 관통 (박근령 먼저 → 그다음 병렬)

⭐⭐ 가장 중요한 분기점 — 박근령이 graph.py를 스텁(빈 껍데기)으로 전체 관통시켜 "증상 넣으면 끝까지 도는 상태"를 공유하면, 그때부터 나머지 4명이 동시에 자기 노드만 채우면 됩니다.
  • □ 박근령: graph 스텁 관통 → 팀 공유
  • □ 박태준: 진료과 문서 작성 + Chroma 적재 (retrieve() 동작)
  • □ 최건: 서버 실행 확인 + 심평원 API curl 테스트 → hira.py
  • □ 고원영: 응급 키워드 + 분류 프롬프트 1차
  • □ 이상현: 요구사항 정의서 완성
2

Phase 2 — 채우고 붙이기

  • □ 박태준: 프론트 chat.html ↔ 백엔드 연결
  • □ 고원영: 분류 완성 → evaluate로 Top-3 측정
  • □ 최건: E-Gen(응급실) 연동 + 발표 준비
  • □ 박근령: 전체 통합·버그 수정

의존 관계 (누가 뭘 먼저 줘야 하나)

박근령: State 스키마 ──→ 최건·고원영·박태준 (다 이 형식에 맞춤)
전원: 진료과 목록 ────→ 박태준(문서)·고원영(분류·평가)·최건(진료과코드)
박근령: 스텁 관통 ────→ 전원 (각자 노드 채우기 시작)
박태준: retrieve() ───→ 고원영 (classify에서 사용)
