Role · 고원영 (상세 가이드)

진료과 분류 · 응급 규칙 · 평가

AI의 "두뇌"에 해당하는 분류 품질과, 안전의 핵심인 응급 판별, 그리고 성능을 숫자로 증명하는 평가를 담당합니다.

3가지 담당 파일 — core/emergency_rules.py(응급), agent/nodes/triage.py·classify.py(판별·분류), eval/(평가). 안전 관련이라 응급 판별을 가장 보수적으로 만드는 게 1순위예요.

PART 1 · 응급 규칙 (가장 중요)

원칙: "놓치지 않는 것(미탐 최소화)"이 최우선. 애매하면 응급으로 분류하는 게 안전해요. 키워드 규칙을 1차로 쓰고, 여유되면 LLM 판단을 보조로.

STEP 1 · emergency_rules.py 보강

EMERGENCY_KEYWORDS = [
    # 의식/신경
    "의식", "의식저하", "의식 저하", "쓰러", "실신", "경련", "발작",
    "마비", "한쪽", "말이 어눌", "발음이", "얼굴이 돌아",
    # 호흡/순환
    "숨", "호흡곤란", "숨을 못", "숨이 안", "숨이 차",
    "가슴", "흉통", "가슴이 찢", "가슴을 쥐어", "식은땀",
    # 출혈/외상
    "피를 많이", "대량 출혈", "토혈", "각혈", "멈추지 않는 피",
    # 기타 위급
    "극심한", "참을 수 없는", "갑자기", "목을 조",
]

def is_emergency(text: str) -> bool:
    """키워드 하나라도 걸리면 응급으로 간주(보수적)."""
    if not text:
        return False
    return any(kw in text for kw in EMERGENCY_KEYWORDS)
보수적으로 — "오탐(응급 아닌데 119 안내)"보다 "미탐(응급인데 놓침)"이 훨씬 위험해요. 키워드는 넉넉하게 넣으세요. 발표 때 "안전을 위해 보수적으로 설계했다"고 설명하면 가점.

STEP 2 · 테스트

python -c "from backend.core.emergency_rules import is_emergency; print(is_emergency('갑자기 가슴이 쥐어짜듯 아파요'), is_emergency('무릎이 시큰해요'))"
# 기대: True False

(선택) LLM 보조 판단을 넣고 싶으면 triage에서 키워드로 1차 거른 뒤, 애매한 경우만 LLM에 "응급 여부"를 물어보는 2단계 구조로. 처음엔 키워드만으로 충분.

PART 2 · 진료과 분류

RAG 근거(박태준의 retrieve()) + LLM으로 Top-3 진료과 + 근거를 생성합니다.

STEP 1 · LLM 설정 (GPT / OpenAI)

우리 팀은 GPT(OpenAI)로 갑니다. (수업에서 제공하는 GPT 키 사용) LangChain으로 연결해요.

pip install langchain-openai        # .env 의 LLM_API_KEY = 수업에서 받은 OpenAI 키
모델 선택 — 분류는 가벼운 작업이라 저렴·빠른 모델로 충분해요. 예: gpt-4o-mini. (수업에서 안내한 모델명이 있으면 그걸로 교체)

STEP 2 · classify.py 구현

LangChain의 구조화 출력(with_structured_output)으로 JSON을 안정적으로 받습니다.

from typing import List
from pydantic import BaseModel, Field

from langchain_openai import ChatOpenAI

from backend.config import LLM_API_KEY
from backend.rag.retriever import retrieve


# LLM이 채워줄 출력 형식
class DeptPick(BaseModel):
    name: str = Field(description="진료과명 (예: 외과)")
    score: float = Field(ge=0, le=1, description="적합도 0~1")
    reason: str = Field(description="이 진료과인 한 줄 근거")

class Classification(BaseModel):
    departments: List[DeptPick]


_llm = ChatOpenAI(model="gpt-4o-mini", api_key=LLM_API_KEY)   # 수업 제공 키
_structured = _llm.with_structured_output(Classification)

PROMPT = """당신은 증상을 듣고 적합한 '진료과'를 안내하는 도우미입니다.
아래 참고 문서를 근거로, 가장 적합한 진료과를 최대 3개까지 고르세요.
각 진료과에 적합도(0~1)와 한 줄 근거를 붙이세요.
질병을 단정하지 말고, 어느 '과'에 가면 되는지만 안내하세요.

[환자 증상]
{symptoms}

[참고 문서 (진료과별 설명)]
{context}
"""


def classify_department(state):
    symptoms = state.get("symptoms", [])
    query = " ".join(symptoms) or state.get("user_input", "")

    docs = retrieve(query, k=3)                        # 박태준의 RAG
    context = "\n\n".join(f"- {d['dept']}: {d['text'][:300]}" for d in docs)

    result = _structured.invoke(PROMPT.format(symptoms=query, context=context))
    # score 내림차순 정렬 후 State에 기록
    depts = sorted((d.model_dump() for d in result.departments),
                   key=lambda d: d["score"], reverse=True)
    return {"departments": depts}
프롬프트 핵심 — ① "진단 아님, 진료과 안내"를 명시 ② 참고 문서(RAG)를 근거로 쓰게 지시 ③ 최대 3개. 이 3가지가 환각을 줄이고 Top-3 평가와도 맞물려요.

PART 3 · 평가 (Top-3 정확도)

Top-3 정확도 = 추천 상위 3개 안에 정답 진료과가 포함된 비율. 분류 품질을 숫자로 증명합니다.

STEP 1 · 테스트셋 작성

eval/testset.csv에 "증상 → 정답 진료과"를 20~30개. (샘플 이미 있음) 실제 흔한 증상 위주로.

symptom,answer_dept
"어제부터 오른쪽 아랫배가 아프고 열이 나요",외과
"가슴이 답답하고 계단 오를 때 숨이 차요",순환기내과
"무릎이 붓고 계단 내려갈 때 시큰거려요",정형외과
...

STEP 2 · 평가 실행

eval/evaluate.py가 각 증상을 분류에 넣고 Top-3 안에 정답이 있는지 셉니다. (이미 작성됨)

python -m eval.evaluate

# 출력 예시:
# [O] 오른쪽 아랫배가 아프고... → ['외과','내과','응급의학과'] (정답: 외과)
# [X] ...
# Top-3 정확도: 17/20 = 85.0%

STEP 3 · 개선 루프

  • 틀린 케이스(X)를 보고 → 해당 진료과 문서(data/departments/)의 증상 설명을 보강 (박태준과 협업)
  • 프롬프트에 자주 헷갈리는 과 구분 기준을 한 줄 추가
  • 다시 evaluate → 숫자 올라가는지 확인
과하게 올리지 말 것 — 85% 정도면 발표용으로 충분해요. 90%를 95%로 올리려 매달리는 게 제일 시간 낭비. 대표 케이스가 잘 되면 OK.
