Role · 박근령 (팀장 · 상세 가이드)

에이전트 코어 · 흐름 설계

당신은 프로젝트의 심장과 뼈대를 담당합니다. 각자 만든 노드를 LangGraph 그래프로 엮어 하나로 돌아가게 하는 것이 목표예요.

가장 중요한 원칙 — ① State 스키마를 맨 먼저 확정하고, ② 스텁(빈 껍데기)으로 전체를 먼저 관통시키세요. 그래야 나머지 4명이 각자 노드를 채워넣기만 하면 됩니다. "완성된 노드를 기다렸다 합치기"는 금물.

STEP 0 · ★ State 스키마 확정 (제일 먼저!)

backend/agent/state.py는 모든 노드가 공유하는 계약입니다. 첫날 팀 회의에서 확정하고 공지하세요. (이미 초안 있음)

from typing import TypedDict, List, Optional

class Department(TypedDict):
    name: str; score: float; reason: str

class Hospital(TypedDict):
    name: str; dept: str; distance_m: int; is_open: bool; phone: Optional[str]

class AgentState(TypedDict, total=False):
    user_input: str            # 이번 턴 사용자 발화
    history: List[dict]        # 이전 대화(Memory)
    symptoms: List[str]        # ① collect
    need_more_info: bool       # ① 되물음 여부
    emergency: bool            # ② triage
    departments: List[Department]   # ③ classify
    location: dict             # {"lat","lng"}
    hospitals: List[Hospital]  # ④ search
    final_message: str         # ⑤ 최종 메시지
LangGraph 동작 원리 — 각 노드는 State를 받아 바뀐 필드만 담은 dict를 return하면, LangGraph가 알아서 State에 병합해 다음 노드로 넘깁니다. 그래서 노드끼리 직접 데이터를 주고받지 않아요 — 전부 State를 통해서.

STEP 1 · 그래프 구조 설계

단일 턴 기준으로 이렇게 흐릅니다. 분기 2개(되물음·응급)가 핵심이에요.

되물음 "루프"는 그래프 안의 순환이 아니에요. 정보가 부족하면 ask로 가서 질문을 담아 턴을 끝냅니다(END). 사용자가 답하면 다음 /api/chat 호출이 history와 함께 다시 collect부터 시작 → 이게 되물음입니다. (그래프 내부 cycle보다 단순·안전)

STEP 2 · 노드 함수 규약

각 담당자에게 이 규약만 전달하면 됩니다. State를 받아 바뀐 필드를 dict로 return.

노드함수읽기쓰기(return)담당

STEP 3 · graph.py 구현

패키지 먼저: pip install langgraph langchain. 확인완료: LangGraph API

from langgraph.graph import StateGraph, START, END

from backend.agent.state import AgentState
from backend.agent.nodes import collect, triage, classify, search


# --- 분기(라우터) 함수: 문자열을 반환하면 그 이름의 노드로 간다 ---
def route_after_collect(state: AgentState) -> str:
    return "ask" if state.get("need_more_info") else "triage"

def route_after_triage(state: AgentState) -> str:
    return "emergency" if state.get("emergency") else "classify"


# --- 메시지를 작성하는 터미널 노드들 ---
def ask_node(state: AgentState) -> dict:
    return {"final_message": "증상을 조금 더 자세히 알려주시겠어요? (언제부터 · 어디가 · 어떻게)"}

def emergency_node(state: AgentState) -> dict:
    return {"final_message": "응급 증상이 의심됩니다. 즉시 119에 연락하거나 가까운 응급실을 방문하세요."}

def respond_node(state: AgentState) -> dict:
    depts = state.get("departments", [])
    if depts:
        msg = f"말씀하신 증상으로는 '{depts[0]['name']}' 진료가 가장 적합해 보여요. 아래 추천 진료과와 주변 병원을 확인해보세요."
    else:
        msg = "추천 진료과를 찾지 못했어요. 증상을 조금 더 알려주시겠어요?"
    return {"final_message": msg}


def build_graph():
    b = StateGraph(AgentState)
    # 노드 등록
    b.add_node("collect", collect.collect_symptoms)
    b.add_node("ask", ask_node)
    b.add_node("triage", triage.check_emergency)
    b.add_node("emergency", emergency_node)
    b.add_node("classify", classify.classify_department)
    b.add_node("search", search.search_hospitals)
    b.add_node("respond", respond_node)
    # 엣지(흐름) 연결
    b.add_edge(START, "collect")
    b.add_conditional_edges("collect", route_after_collect,
                            {"ask": "ask", "triage": "triage"})
    b.add_edge("ask", END)
    b.add_conditional_edges("triage", route_after_triage,
                            {"emergency": "emergency", "classify": "classify"})
    b.add_edge("emergency", END)
    b.add_edge("classify", "search")
    b.add_edge("search", "respond")
    b.add_edge("respond", END)
    return b.compile()


# 앱 시작 시 1회만 컴파일해 재사용
_graph = None
def get_graph():
    global _graph
    if _graph is None:
        _graph = build_graph()
    return _graph
노드가 full State를 return해도 OK지만(현재 스텁이 그럼), 권장은 바뀐 필드만 return. 예: triage는 return {"emergency": True}. 팀에 이 규약으로 통일해 공지하세요.

STEP 4 · run_agent (요청 ↔ State ↔ 응답 변환)

FastAPI가 호출하는 진입점. ChatRequest를 State로 바꿔 그래프를 돌리고, 결과 State를 ChatResponse로 변환합니다.

from backend.api.schemas import ChatRequest, ChatResponse, DepartmentOut, HospitalOut

def run_agent(req: ChatRequest) -> ChatResponse:
    state = {
        "user_input": req.message,
        "history": req.history,
        "location": {"lat": req.lat, "lng": req.lng},
    }
    final = get_graph().invoke(state)          # ← 그래프 실행

    return ChatResponse(
        reply=final.get("final_message", ""),
        emergency=final.get("emergency", False),
        need_more_info=final.get("need_more_info", False),
        departments=[DepartmentOut(**d) for d in final.get("departments", [])],
        hospitals=[HospitalOut(**h) for h in final.get("hospitals", [])],
    )

STEP 5 · 스텁으로 전체 관통 테스트

다른 노드가 비어 있어도(스텁) 그래프는 끝까지 돌아야 합니다. 이게 되면 각자 노드만 채우면 완성.

# 그래프 단독 테스트
python -c "from backend.agent.graph import run_agent; from backend.api.schemas import ChatRequest; print(run_agent(ChatRequest(message='무릎이 아파요', lat=37.5665, lng=126.9780)))"

# 서버로 테스트
uvicorn backend.main:app --reload
# → http://localhost:8000/api/health 로 서버 확인
통합 담당자의 핵심 역할 — "스텁으로 전체가 돌아가는 상태"를 1~2일 안에 만들어 팀에 공유하세요. 그 뒤엔 각자 자기 노드를 채우며 바로바로 /api/chat으로 확인할 수 있습니다.

(선택) 턴 간 메모리 강화

지금은 프론트가 보내주는 history로 맥락을 유지합니다. 더 견고하게 하려면 LangGraph checkpointer(MemorySaver) + thread_id로 서버가 대화를 기억하게 할 수 있어요. 처음엔 history 방식으로 충분하니 여유 생기면 업그레이드하세요.

통합 담당자 주의사항

  • 공유 계약 파일(state.py, main.py)은 당신 소유 — 변경 시 팀 공지
  • schemas.py는 최건과 협의해 확정 (State ↔ 응답 매핑이 맞아야 함)
  • 노드 import는 from backend.agent.nodes import ... 형태 유지 (순환 import 주의)
  • PR 리뷰어 역할: 각자 노드가 State 규약을 지키는지 확인하고 병합
