State · 공유 계약

State — 에이전트의 "메모지"

모든 노드가 같이 쓰는 데이터 한 덩어리예요. 이 구조를 처음에 딱 정해야 각자 병렬로 개발할 수 있어요.

한 줄 비유 — State는 병원 차트(메모지) 한 장. 접수 → 간호사 → 의사… 거치는 곳마다 그 차트에 계속 추가로 적어나가는 것과 똑같아요. 아무것도 지우지 않고 추가만 해요.

1. State란?

에이전트는 State라는 딕셔너리를 만들어서, 각 단계(노드)가 거기에 자기 결과를 채워 넣고 다음 단계로 넘겨요. backend/agent/state.py는 "그 메모지에 어떤 칸들이 있는지"를 정의한 설계도예요.

왜 중요? 모든 팀원이 같은 메모지를 쓰기 때문에, 칸 이름(symptoms, departments …)이 처음에 딱 고정돼야 각자 그 이름에 맞춰 코딩할 수 있어요. 중간에 바꾸면 전부 꼬여요.

2. 칸(필드) 전체

칸의미채우는 단계 (담당)
user_input이번 턴 사용자 발화입력
history이전 대화 (Memory)입력
location사용자 위치 {lat, lng}입력
symptoms추출된 핵심 증상① 증상 수집 박근령
need_more_infoTrue면 되물음① 증상 수집 박근령
emergencyTrue면 119 분기② 응급 판별 박태준
departments추천 진료과 Top-N + 근거③ 분류 박태준
hospitals주변 병원/약국/응급실④ 검색 최건
final_message최종 안내 메시지⑤ 결과 박근령

3. 리스트 안의 "모양" (제일 중요한 계약)

departments·hospitals는 리스트인데, 그 안의 항목이 어떤 모양인지를 맞춰야 해요. 이게 분류(박태준)·검색(최건)이 지켜야 할 약속이에요.

# 진료과 1개
{ "name": "정형외과", "score": 0.9, "reason": "무릎 통증 → 관절 질환" }

# 병원 1개
{ "name": "튼튼정형외과", "dept": "정형외과",
  "distance_m": 320, "is_open": true, "phone": "02-000-0000" }

4. 데이터 흐름 — 메모지가 채워지는 과정

"무릎이 3일째 아파요" 한 번의 여정. 메모지가 단계마다 추가로 채워지는 걸 그대로 볼게요.

0

시작 (입력)

{ "user_input": "무릎이 3일째 아파요",
  "location": {"lat": 37.56, "lng": 126.97} }
1

증상 수집 → symptoms, need_more_info 추가

{ ..., "symptoms": ["무릎 통증"], "need_more_info": false }

정보 부족했으면 need_more_info: true → 되묻고 턴 종료.

2

응급 판별 → emergency 추가

{ ..., "emergency": false }

true였으면 분류 건너뛰고 119 안내로 분기.

3

진료과 분류 → departments 추가

{ ..., "departments": [
    {"name": "정형외과", "score": 0.9, "reason": "무릎 통증 → 관절 질환"}
]}
4

병원 검색 → hospitals 추가

{ ..., "hospitals": [
    {"name": "튼튼정형외과", "dept": "정형외과", "distance_m": 320, "is_open": true}
]}
5

결과 안내 → final_message 추가 → 사용자에게

{ ..., "final_message": "정형외과 진료를 권해드려요. 근처 '튼튼정형외과'(320m)를 확인해보세요." }

이 완성된 메모지에서 꺼내 화면에 표시 → final_message(말풍선), departments(추천카드), hospitals(병원목록).

5. 노드 = 함수 (읽고 → 쓰고 → 넘김)

각 노드는 메모지를 받아 → 알아낸 칸만 dict로 return하면 LangGraph가 자동으로 합쳐줘요.

def check_emergency(state):        # 메모지를 받음
    text = state["user_input"]      # 메모지에서 '사용자 말'을 읽음
    return {"emergency": is_emergency(text)}   # 'emergency' 칸만 적어서 돌려줌
규약 — 노드는 바뀐 칸만 return. 전체 state를 돌려줘도 되지만, 바뀐 칸만 주는 게 깔끔해요. 서로 데이터를 직접 주고받지 않고 전부 State를 통해서.

6. 왜 "제일 먼저" 확정해야 하나

  • 박태준(분류)은 symptoms를 읽고 departments를 씀
  • 최건(검색)은 departments를 읽고 hospitals를 씀
  • 박태준(프론트)은 departments·hospitals를 받아서 화면에 그림

→ 칸 이름이 고정돼야 각자 그 이름에 맞춰 동시에 개발 가능해요. 그래서 "박근령이 맨 처음 확정·공지"가 1순위.
