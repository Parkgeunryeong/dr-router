Role · 고원영 (상세 가이드)

RAG · 지식베이스

진료과 문서를 Chroma에 올려 검색(RAG)을 제공합니다. "작게" 가는 게 핵심이에요.

RAG의 역할 — 분류 담당(박태준)의 classify.py가 retrieve(query)를 호출하면, 증상과 관련된 진료과 문서를 돌려줘서 LLM이 근거 있게 분류하도록 돕는 것. 당신은 retrieve()가 잘 동작하게만 만들면 됩니다.

STEP 1 · 진료과 문서 작성

data/departments/ 폴더에 진료과 하나당 파일 하나(내과.md, 정형외과.md …)로 10~20개. 각 문서는 3~5문장이면 충분해요. (예시 파일 data/departments/내과.md 이미 있음)

# 정형외과

## 대표 증상
- 무릎/어깨/허리 통증, 관절이 붓고 시큰거림
- 삐끗함, 골절 의심, 디스크

## 담당 질환
- 관절염, 인대 손상, 척추 질환, 골절

## 안내 포인트
- 외상 직후 심한 부기·변형이면 응급/외과 고려.
왜 작게? — "증상 → 진료과" 분류는 질환백과 전체가 아니라 진료과별 요약 문서면 충분해요. 적을수록 적재·검색이 빠르고 품질 확인도 쉽습니다. (진료과 목록은 팀 회의에서 확정)

STEP 2 · 패키지 설치

# requirements.txt 의 주석 해제 후
pip install chromadb sentence-transformers
임베딩 모델은 처음 1회 자동 다운로드됩니다(수백 MB, 인터넷 필요). 이후엔 캐시에서 로드. GPU 없어도 문서 10~20개는 CPU로 금방 됩니다.

STEP 3 · retriever.py (컬렉션 + 검색)

컬렉션 생성 로직을 여기 한 곳에 두고 build_index.py가 가져다 씁니다. 확인완료: Chroma API

import chromadb
from chromadb.utils import embedding_functions

CHROMA_DIR = "backend/rag/chroma_db"
COLLECTION = "departments"
# 한국어 경량 임베딩 (기본값). 품질 더 원하면 "BAAI/bge-m3" (더 무거움)
MODEL = "jhgan/ko-sroberta-multitask"

_col = None

def get_collection():
    """Chroma 컬렉션을 1회 생성해 재사용."""
    global _col
    if _col is None:
        client = chromadb.PersistentClient(path=CHROMA_DIR)
        emb = embedding_functions.SentenceTransformerEmbeddingFunction(model_name=MODEL)
        _col = client.get_or_create_collection(
            name=COLLECTION,
            embedding_function=emb,
            metadata={"hnsw:space": "cosine"},   # 코사인 유사도
        )
    return _col


def retrieve(query: str, k: int = 3):
    """증상 쿼리로 관련 진료과 문서 Top-k 반환."""
    col = get_collection()
    res = col.query(query_texts=[query], n_results=k)
    docs  = res["documents"][0]
    metas = res["metadatas"][0]
    dists = res["distances"][0]
    return [
        {"dept": m.get("dept"), "text": d, "score": round(1 - dist, 3)}
        for d, m, dist in zip(docs, metas, dists)
    ]

STEP 4 · build_index.py (문서 적재)

문서를 읽어 컬렉션에 upsert(있으면 갱신, 없으면 추가). 최초 1회 + 문서 바뀔 때마다 실행.

from pathlib import Path
from backend.rag.retriever import get_collection

DATA_DIR = Path("data/departments")

def main():
    col = get_collection()
    ids, documents, metadatas = [], [], []
    for p in sorted(DATA_DIR.glob("*.md")):
        ids.append(p.stem)                       # 파일명 = 진료과명 = id
        documents.append(p.read_text(encoding="utf-8"))
        metadatas.append({"dept": p.stem})
    if not ids:
        print("문서가 없습니다: data/departments/*.md 를 먼저 작성하세요.")
        return
    col.upsert(ids=ids, documents=documents, metadatas=metadatas)
    print(f"적재 완료: {len(ids)}개 진료과 문서")

if __name__ == "__main__":
    main()

STEP 5 · 실행 & 검색 테스트

# 1) 적재 (최초 1회)
python -m backend.rag.build_index

# 2) 검색 테스트 (파이썬 셸)
python -c "from backend.rag.retriever import retrieve; print(retrieve('무릎이 붓고 시큰거려요'))"

결과로 정형외과 문서가 상위에 나오면 성공. score가 높을수록(1에 가까울수록) 유사.

여기까지 되면 RAG 끝. 분류(박태준)가 retrieve()를 가져다 쓰면 됩니다. 정확도 튜닝은 문서 문구를 다듬는 정도로 충분 — 과하게 안 해도 돼요.

협업 포인트

  • 박태준(분류): retrieve()의 반환 형식(dept, text, score)을 맞춰 쓰도록 공유
  • 진료과 문서 내용: 분류가 자주 틀리는 과가 있으면 박태준과 상의해 해당 문서 보강

최종 체크리스트

  • □ data/departments/에 진료과 문서 10~20개
  • □ python -m backend.rag.build_index → "적재 완료"
  • □ retrieve("...")가 관련 진료과 문서 반환
  • □ 박태준(분류)이 retrieve()를 쓸 수 있게 형식 공유
